# 罗马帘入库后缩略图为白图：分析与修复（SU LinkHub v0.13.7.10）

## 现象
- `单独罗马帘模型.skp` 入库后，模型库卡片缩略图是白色。点刷新后仍是白色。
- SketchUp 自己的模型预览（`meta/model_thumbnail.png`）正常，能看到米色罗马帘。所以模型几何没有问题。
- 模型内组件缩略图（`thumbnails/长条罗马帘#1.jpg`）几乎全白。主体颜色约为 (240,240,232)~(244,240,232)。

## 关键证据
- 材质 `Linen Milk` 的贴图平均色是 (244,240,234)。这与白图中主体的颜色一致。所以缩略图角度很可能看到的是这块米白衬布面。
- 材质 `fabric MIDDLE1`（199,191,178）是正面米色布。用户视角看到的是这一面。
- `model.dat` 约 18 MB，是高模平滑网格。平滑网格没有硬边线，只有轮廓线能画出外形。

## 根因（插件端）
1. **缩略图渲染关闭了轮廓线**：`apply_soft_thumbnail_render_options!` 设置 `DrawSilhouettes = false`，背景纯白，灯光 Light 80 / Dark 20。米白材质在白背景上没有任何边界。
2. **白底校正把浅色家具当成背景抹白**：`normalize_soft_thumbnail_white_background!` 从画面边缘做洪水填充，容差固定 34。米白 (244,240,234) 与白色距离约 28，小于 34，整件家具被填成纯白。
   - 离线复现：同一张无轮廓的米白主体图，旧代码校正后主体像素 3264 → 0；新代码保持 3264（`tests/thumbnail_white_background_test.rb`）。
3. **验收只看四角亮度**：`soft_thumbnail_white_background?` 只检查四角是否够白。白图的四角当然是白的，所以白图被当作“成功”写入缓存。
4. **先覆盖后校正**：`extract_soft_model_embedded_thumbnail` 先把提取图移到正式缩略图位置，再做白底校正。校正抹白后，正式缩略图已经变成白图。
5. **刷新为什么仍是白**：刷新走轴测视图渲染。米白主体在无轮廓、强光照下接近 245 阈值，可能被主体检测判为空白。判为空白时插件保留旧图，旧图就是第 2~4 步产生的白图。

## 修复内容（v0.13.7.10）
- 缩略图渲染开启 1px 轮廓线（`DrawSilhouettes = true`，`SilhouetteWidth = 1`）。
- 白底校正：原图已是白底时，容差从 34 降到 6；灰底恢复仍用 34。
- 白底校正后若主体像素几乎全部消失，撤销本次抠白（`soft_thumbnail_fill_erased_subject?`）。
- 内置缩略图提取与源 SKP 缓存写入：增加主体像素验收；先在临时文件上校正和验收，通过后才替换正式缩略图。

## 用户侧规避（不升级插件时）
- 在模型库卡片上点“⇄ 反转”，切到米色正面那一侧的视图。
- 入库前把衬布材质 `Linen Milk` 换成稍深的颜色，或让外侧面朝向缩略图相机。
- 在样式中打开“轮廓线”后再入库，SketchUp 写入的内置缩略图就有外形边界。
- 清理未使用组件（窗口 → 模型信息 → 统计信息 → 清除未使用项），删除残留的 `Sree` 人物组件和材质。
- 升级到 v0.13.7.10 后，对已入库的白图模型点一次“⟳ 刷新”。

## 限制
- 本机为 Linux，无法运行 SketchUp。修复只做了 Ruby 语法检查和离线像素测试，需要在 SketchUp 2026 中实际验证。
